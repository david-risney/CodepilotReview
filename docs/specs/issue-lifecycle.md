# Issue Lifecycle Spec

## Overview
Review issues follow a lifecycle from discovery to resolution. The available statuses vary by provider.

## Internal Statuses (all providers)
- **suggested**: AI/tool-generated, pending user triage
- **draft**: Accepted by user, but not yet published to the provider
- **dismissed**: User decided this is not a real issue

## Provider Statuses

### GitHub
| Status | Description | API |
|--------|-------------|-----|
| **published** | Active/open thread | GraphQL `unresolveReviewThread` |
| **resolved** | Thread resolved | GraphQL `resolveReviewThread` |

- Edit own comments: ✅ `PATCH /repos/{owner}/{repo}/pulls/comments/{id}`
- Delete own comments: ✅ `DELETE /repos/{owner}/{repo}/pulls/comments/{id}`
- Thread resolution: ✅ **GraphQL only** — REST has no resolve/unresolve endpoints
- Note: `viewerCanUpdate` / `viewerCanDelete` on GraphQL `PullRequestReviewComment` can be queried to check permissions

### Azure DevOps (ADO)
| Status | API Value | `CommentThreadStatus` Enum |
|--------|-----------|---------------------------|
| **published** | `active` (1) | Active |
| **pending** | `pending` (6) | Pending — awaiting response |
| **resolved** | `fixed` (2) | Fixed (UI shows "Resolved") |
| **closed** | `closed` (4) | Closed |
| **wontFix** | `wontFix` (3) | Won't Fix |
| **byDesign** | `byDesign` (5) | By Design |

- Edit own comments: ✅ `PATCH .../threads/{threadId}/comments/{commentId}`
- Delete own comments: ✅ Soft delete (`isDeleted` flag, not permanent)
- Thread status: ✅ `PATCH .../threads/{threadId}` with `{ status: <int> }`
- Status lives on the **thread**, not individual comments
- Editing/deleting others' comments requires "Manage pull requests" or Project Admin permissions

### Chromium (Gerrit)
| Status | Description | API Field |
|--------|-------------|-----------|
| **published** | Unresolved thread | `unresolved: true` |
| **resolved** | Resolved thread | `unresolved: false` |

- Edit published comments: ❌ **Not possible** — published comments are immutable
- Delete published comments: ❌ **Admin-only** redaction (replaces body text, not a true delete)
- Edit/delete draft comments: ✅ Full CRUD via `/changes/{id}/revisions/{rev}/drafts/{id}`
- Thread state: Determined by the **last** comment's `unresolved` value in the thread
- Publishing drafts: via `POST .../review` with `draft_handling: "PUBLISH"`

### Local
| Status | Description |
|--------|-------------|
| **suggested** | AI/tool suggested |
| **draft** | User created/accepted |
| **resolved** | Addressed |
| **dismissed** | Rejected |

- Edit: ✅ (local storage)
- Delete: ✅ (local storage)
- No external publishing

## Sources
- `tool`: Generated by a review tool (built-in or custom)
- `ai`: Generated by AI review prompt
- `user`: Manually created by the user
- `provider`: Loaded from an existing provider comment

## Triage Flow
1. Review tools produce issues with status `suggested`
2. User sees a triage QuickPick to select which issues to keep
3. Selected issues are promoted to `draft`
4. User can also create issues manually (status `draft`)
5. Draft issues can be published to the provider
6. Published issues can be resolved, closed, or set to other provider-specific statuses

## Replies
- Replies are `ReviewIssue` objects with `parentIssueId` set
- Created as `draft` status, published via "Publish Draft Comments"
- GitHub: `POST /repos/{owner}/{repo}/pulls/comments/{id}/replies`
- ADO: `POST .../threads/{threadId}/comments` with `parentCommentId`
- Gerrit: Draft comment with `in_reply_to` field, published via `Set Review`
- `publishAllDrafts()` publishes parent issues first, then replies

## Issue Fields
- `summary`: TLDR sentence
- `details`: Full description
- `command`: Command to reproduce/see the issue
- `position`: File path, line number, side (base/head)
- `suggestedFix`: Optional fix (workspace edit, suggested change, chat prompt, or patch)
- `providerCommentId`: Provider-specific comment ID (set after publishing)
- `parentIssueId`: ID of parent issue (for replies)
- `providerStatus`: Raw provider-specific status string for round-tripping
