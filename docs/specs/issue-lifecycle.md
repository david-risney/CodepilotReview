# Issue Lifecycle Spec

## Overview
Review issues follow a lifecycle from discovery to resolution.

## Statuses
- **suggested**: AI/tool-generated, pending user triage
- **draft**: Accepted by user, but not yet published to the provider
- **published**: Pushed to the provider (GitHub/ADO/Chromium) as a comment
- **dismissed**: User decided this is not a real issue
- **resolved**: Issue has been addressed

## Sources
- `tool`: Generated by a review tool (built-in or custom)
- `ai`: Generated by AI review prompt
- `user`: Manually created by the user
- `provider`: Loaded from an existing provider comment

## Triage Flow
1. Review tools produce issues with status `suggested`
2. User sees a triage QuickPick to select which issues to keep
3. Selected issues are promoted to `draft`
4. User can also create issues manually (status `draft`)
5. Draft issues can be published to the provider
6. Published issues can be resolved or dismissed

## Issue Fields
- `summary`: TLDR sentence
- `details`: Full description
- `command`: Command to reproduce/see the issue
- `position`: File path, line number, side (base/head)
- `suggestedFix`: Optional fix (workspace edit, suggested change, chat prompt, or patch)
